Architecture

Browser to control plane to Mac mini to macOS VM. The minis dial out only; the public edge is a Cloudflare Tunnel, so no host needs a public IP or port forwarding.

Two hostnames, one origin

Both public hostnames route to the same server:5496; the server keys on the Host header (requireWorkerHost / requireBrowserHost). Requests on the wrong host get a 404.

  • Worker host — /install.sh, /api/v1/workers/register, heartbeat, VM state, /releases/*, pending proxy sessions. No Cloudflare Access (Bearer-token auth).
  • Browser host — /api/v1/me, /my-workstation*, /browser/*. Cloudflare Access; the origin validates Cf-Access-Jwt-Assertion.

Confining member endpoints to the Access host is itself a security control: the unprotected worker host cannot reach them.

Terminal

The browser opens GET /api/v1/browser/terminal/ws. Cloudflare Access authenticates the upgrade, then the server bridges SSH on its side, so the browser only needs xterm.js. Input and resize travel as JSON; output returns as binary frames.

VNC relay

  1. Browser creates a proxy session (POST /api/v1/browser/proxy-sessions, port 5900).
  2. The worker polls GET /api/v1/proxy/sessions/pending and picks it up.
  3. Both sides connect GET /api/v1/proxy/ws — one role=client, one role=worker — and the server relays bytes between the two sockets.
  4. The worker bridges TCP to the VM’s 5900 on the local network.

Design decisions

  • REST + WebSocket only; workers talk to the server over HTTPS plus WebSocket proxy sessions.
  • TLS terminates at the Cloudflare edge; the origin stays plain HTTP on the compose network. Workers pin the certificate fingerprint they observe (the edge cert).
  • The frontend is built by Docker and baked into the server image; the Go server serves it.
  • Workers check for new releases on heartbeat; the server validates Mach-O code signatures on upload against a required signing identity.
  • VNC rides the WebSocket relay; the browser terminal uses a server-side SSH bridge.
