Deploy

End-to-end runbook: build and ship the server image, bring up the compose stack, configure the Cloudflare tunnel and Access, wire the config, publish a signed worker, and enroll a Mac mini.

On this page Build & ship Bundle Bring up Cloudflare Config Publish worker Enroll mini

1 · Build the image locally and ship it

Build for linux/amd64 off-host (cross-compile natively, then assemble a small image) and load it over SSH. This keeps a disk-tight server from running a multi-stage build.

cd frontend && pnpm install --frozen-lockfile && pnpm build && cd ..
cd server && GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go build -trimpath \
  -o /tmp/mc-build/minicontrol-server ./cmd/minicontrol-server && cd ..
cp -r frontend/dist /tmp/mc-build/frontend
docker buildx build --platform linux/amd64 -t minis-server:latest \
  -o type=docker,dest=/tmp/mcs-amd64.tar /tmp/mc-build
gzip -c /tmp/mcs-amd64.tar | ssh root@<host> 'gunzip | docker load'

The compose server service references image: minis-server:latest with pull_policy: never (no build:), so the host never builds or pulls it.

2 · Stage the bundle

Deploy a self-contained directory with compose.yml, .env, deploy/config.yaml, deploy/migrations/, and install/setup-host.sh. The compose project name is the directory name.

3 · Bring up core, then the tunnel

docker compose up -d postgres server   # migrations auto-apply on fresh init
docker compose exec -T server wget -qO- http://127.0.0.1:5496/api/v1/health  # {"status":"ok"}
# set CLOUDFLARED_TOKEN in .env, then:
docker compose up -d cloudflared        # logs: "Registered tunnel connection"

4 · Cloudflare

One named tunnel, two public hostnames, both routed to http://server:5496:

  • worker host — no Access policy (workers use Bearer tokens, cannot SSO).
  • browser host — an Access application with email auth.

Keep one Access app; its AUD and team domain feed the config. You can read both off the browser host’s 302 Location (kid=<AUD> and the <team>.cloudflareaccess.com host).

5 · Wire the config, then restart

A mounted-file edit does not auto-restart the container, and config is read only at startup — restart after editing:

docker compose restart server

Keys: worker_public_hostname, browser_public_hostname, access_team_domain, access_aud, required_signing_identity. Setting the two hostnames confines member endpoints to the Access host and worker endpoints to the token host.

curl -s -o /dev/null -w '%{http_code}\n' https://<worker-host>/install.sh    # 200
curl -s -o /dev/null -w '%{http_code}\n' https://<worker-host>/api/v1/me      # 404 (browser-only)
curl -s -o /dev/null -w '%{http_code}\n' https://<browser-host>/             # 302 -> Access

6 · Publish the signed worker

From a Mac with a Developer ID certificate and a notary keychain profile:

CODE_SIGN_IDENTITY="Developer ID Application: ... (TEAMID)" \
NOTARY_KEYCHAIN_PROFILE="<profile>" \
scripts/build-and-publish.sh \
  --server https://<worker-host> \
  --token <admin_token> \
  --version <ver>

7 · Enroll the Mac mini

echo '<enrollment_token>' > ~/mini-control-enroll.key
curl -fsSL https://<worker-host>/install.sh | sudo bash

Installs tart, pulls the macOS base image (slow), installs the worker, registers, builds the VM pool, then auto-reboots. Confirm via GET /api/v1/workers or the browser UI.
