Mini Control

A Mac mini cluster management system for browser-controlled macOS VMs. A Go control plane coordinates Swift workers on Mac mini hosts and serves a React frontend for browser terminal and desktop access.

Capabilities

  • Control plane: a Go server for worker registration, heartbeats, VM state, proxy sessions, and signed release distribution.
  • Worker: a Swift daemon that drives tart macOS VMs, maintains a per-host VM pool, and relays VNC/SSH back through the server.
  • Browser UI: a React + TypeScript app served by the Go server, with an xterm.js terminal and VNC remote desktop over WebSocket.
  • Dedicated workstations: each member can claim a persistent macOS VM, resumed and moved across workers on demand.
  • Zero inbound exposure: Mac minis dial out only; the public edge is a Cloudflare Tunnel.
  • Auth split: Cloudflare Access (email) for the browser, Bearer tokens for workers, with host-based routing keeping the two apart.
  • Auto-update: workers check for newer signed releases on heartbeat; uploads are validated against a required Mach-O signing identity.

Components

ComponentRole
server/Go control plane + WebSocket relay; serves the baked-in React frontend and distributes worker binaries.
worker/Swift launchd daemon on each Mac mini: registers, heartbeats, manages tart VMs, relays proxy sessions.
frontend/React + TypeScript (pnpm + Vite) browser UI for terminal and remote desktop.

Request model

Communication is REST plus WebSocket proxy sessions. The browser and workers reach the same origin through two Cloudflare public hostnames; the server distinguishes them by Host header.

Install the worker

On an Apple Silicon Mac mini, place the enrollment token and run the setup script served by the control plane:

echo '<enrollment_token>' > ~/mini-control-enroll.key
curl -fsSL https://<worker-host>/install.sh | sudo bash

The script installs tart, pulls the macOS base image, installs the worker binary, registers with the server, builds the VM pool, then reboots to apply system tuning.
